### SHYNI SCAN

수신된 항목을 shyni 서버로 하나씩 직렬로 처리합니다.

- 항목마다 **VFS 새로고침 → 스캔 전송 → job 결과 확인**이 끝나야 다음 항목을 시작합니다.
- 동시에 실행 중인 스캔 수는 스캔 설정의 **동시 스캔 수**(기본 1)로 제한합니다.
  수신이 한꺼번에 몰려도 shyni에 한 번에 보내지 않습니다.

- MODE
    - ADD : 신규 항목 스캔 (전송 전 VFS 새로고침)
    - REMOVE_FILE / REMOVE_FOLDER : 삭제 스캔
    - REFRESH : 해당 경로의 메타데이터 새로고침. 항목이 아직 없으면 먼저 등록 스캔 후 새로고침합니다.

- API
    * URL : /shyni_mate/api/scan/do_scan
    * PARAM
        - target : 경로
        - mode: 기본 ADD (optional)
        - target_section_id : (optional)
        - callback_id : (optional)
        - callback_url : (optional)
        - apikey : apikey (필수)

    * VFS 새로고침만 : /shyni_mate/api/scan/vfs_refresh (target, recursive, async)
    * 메타데이터 새로고침 : /shyni_mate/api/scan/manual_refresh (metadata_item_id)

----

### 동작 방식

1. 파일체크 주기(기본 60초)마다 READY 항목을 오래된 순으로 확인합니다.
2. 실행 중인 shyni job이 동시 스캔 수 미만일 때만 다음 항목을 전송합니다.
   - ADD: 설정이 켜져 있으면 먼저 rclone RC로 대상 경로를 VFS 새로고침(recursive)합니다.
   - 경로를 샤이니 경로 매핑 규칙으로 변환한 뒤, `/compat/section_by_path`로 섹션을 찾고
     `POST /library/sections/{id}/refresh`로 부분 스캔을 전송합니다.
   - GDS 수신 원문에 ffprobe 자료가 있으면 함께 전달해 shyni의 분석을 생략시킵니다.
3. 전송된 job은 매 주기 `/compat/jobs/{job_id}`로 폴링해 완료/실패를 확정합니다.
4. 완료되면 항목이 FINISH_SHYNI가 되고, 등록된 callback으로 결과를 통지합니다.

### 상태 의미

스캔 목록의 상태 필터와 항목에 표시되는 상태입니다.

- 준비: 아직 shyni에 보내지 않은 항목입니다. 파일체크 주기마다 오래된 순으로 처리되고, 설정된 스캔 수에 맞춰 전송됩니다.
- ffprobe 대기 중: 파일이 많은 항목은 ffprobe 데이터가 여러 개로 나뉘어 전송됩니다. shyni에 보냈지만 아직 데이터가 다 모이지 않은 상태로, 옆에 (받은 수/전체 수)가 표시됩니다. 30분이 지나도 전체 데이터가 모이지 않을 경우, shyni가 받은 데이터만으로 스캔을 진행합니다.
- 스캔 대기 중: 데이터가 다 모였거나 데이터가 없는 항목으로, shyni에 스캔을 보냈지만 아직 시작되지 않은 상태입니다. 같은 라이브러리의 앞선 스캔이 끝나야 차례가 옵니다.
- 진행중: shyni가 지금 이 항목을 스캔하고 있는 상태입니다.
- 완료: 스캔이 끝난 항목입니다.
- 이미 반영됨: 스캔은 끝났지만 새로 등록된 것이 없는 항목입니다. 이미 shyni에 반영돼 있던 내용입니다.
- 실패: 스캔이 실패로 끝난 항목입니다. 사유에 따라 아래로 나뉩니다.
    - 라이브러리 없음: 항목 경로에 맞는 shyni 라이브러리를 찾지 못했습니다.
    - 항목 없음: 라이브러리는 찾았지만 그 안에서 항목을 찾지 못했습니다.
    - job 실패: shyni 스캔 작업(job) 자체가 실패로 끝났습니다.

### rclone vfs/refresh 연동

스캔 경로가 규칙에 매칭되면 rc addr에 호출하여 vfs/refresh를 수행합니다.

* 규칙 형식: `{로컬 경로}|{리모트 경로}|{rc 주소}#{VFS 이름}|{user}|{pass}` (user/pass·#VFS는 옵션)
* 대상의 부모부터 OK를 받을 때까지 상위로 올라가며 새로고침한 뒤, 대상 폴더를 recursive로 새로고침합니다.
* rclone 플러그인이 설치되어 있어야 합니다 (rclone 실행 파일 경로를 그 설정에서 읽습니다).

### 설정

- 기본 설정: shyni 주소 / shyni 토큰 (연결 테스트 버튼으로 라이브러리 조회 확인 가능)
- 스캔 설정: 동시 스캔 수, 스캔 대기 시간(shyni wait), 파일체크 주기,
  VFS 새로고침 사용 여부와 규칙, 샤이니 경로 매핑, DB 자동 삭제
