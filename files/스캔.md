### SHYNI SCAN

수신된 항목을 shyni 서버로 하나씩 직렬로 처리합니다.

- 항목마다 **VFS 새로고침 → 스캔 전송 → job 결과 확인**이 끝나야 다음 항목을 시작합니다.
- 동시에 실행 중인 스캔 수는 스캔 설정의 **동시 스캔 수**(기본 1)로 제한합니다.
  수신이 한꺼번에 몰려도 shyni에 한 번에 보내지 않습니다.

- MODE
    - ADD : 신규 항목 스캔 (전송 전 VFS 새로고침)
    - `REMOVE_FILE` / `REMOVE_FOLDER` : 삭제 스캔
    - REFRESH : 해당 경로의 메타데이터 새로고침. 항목이 아직 없으면 먼저 등록 스캔 후 새로고침합니다.

- API
    * URL : `/shyni_mate/api/scan/do_scan`
    * PARAM
        - target : 경로
        - mode: 기본 ADD (optional)
        - `target_section_id` : (optional)
        - `callback_id` : (optional)
        - `callback_url` : (optional)
        - apikey : apikey (필수)

    * VFS 새로고침만 : `/shyni_mate/api/scan/vfs_refresh` (target, recursive, async)
    * 메타데이터 새로고침 : `/shyni_mate/api/scan/manual_refresh` (`metadata_item_id`)

----

### 동작 방식

1. 파일체크 주기(기본 60초)마다 READY 항목을 오래된 순으로 확인합니다.
2. 실행 중인 shyni job이 동시 스캔 수 미만일 때만 다음 항목을 전송합니다.
    - ADD: 설정이 켜져 있으면 먼저 rclone RC로 대상 경로를 VFS 새로고침(recursive)합니다.
    - 경로를 샤이니 경로 매핑 규칙으로 변환한 뒤, `/compat/section_by_path`로 섹션을 찾고
      `POST /library/sections/{id}/refresh`로 부분 스캔을 전송합니다.
    - GDS 수신 원문에 ffprobe 자료가 있으면 함께 전달해 shyni의 분석을 생략시킵니다.
    - 디스크 대기가 높으면 새 전송을 한 주기 미룹니다 (스캔 설정의 '디스크가 바쁠 때 스캔 양보', 기본 켜짐).
      이미 전송된 항목의 확인은 계속됩니다.
3. 전송된 job은 매 주기 `/compat/jobs/{job_id}`로 폴링해 완료/실패를 확정합니다.
4. 완료되면 항목이 FINISH_SHYNI가 되고, 등록된 callback으로 결과를 통지합니다.

### 상태 의미

스캔 목록의 상태 필터와 항목에 표시되는 상태입니다.

- 준비: 아직 shyni에 보내지 않은 항목입니다. 파일체크 주기마다 오래된 순으로 처리되고, 설정된 스캔 수에 맞춰 전송됩니다.
- 보류: Shyni 연동이 꺼져 있는 동안 쌓인 항목입니다. 연동을 켜도 자동으로 처리되지 않으며, 목록에서 보류 해제를 해야 처리가 시작됩니다.
- ffprobe 대기 중: 파일이 많은 항목은 ffprobe 데이터가 여러 개로 나뉘어 전송됩니다. shyni에 보냈지만 아직 데이터가 다 모이지 않은 상태로, 옆에 (받은 수/전체 수)가 표시됩니다. 30분이 지나도 전체 데이터가 모이지 않을 경우, shyni가 받은 데이터만으로 스캔을 진행합니다.
- 스캔 대기 중: ffprobe 데이터는 다 모였지만 shyni가 아직 스캔을 시작하지 않은 상태입니다. 스캔 작업이 등록만 되고 차례를 기다리는 경우도 포함됩니다.
- 진행중: shyni가 지금 이 항목을 스캔하고 있는 상태입니다.
- 분석중: 전송 후 analyze 단계에서 스캔 설정의 analyze 대기 시간 이상 머물고 있는 항목입니다. 동시 스캔 수에서는 제외되며, shyni가 스캔을 끝내면 정상적으로 완료 처리됩니다. 단, analyze 후 대기 시간까지 끝나지 않으면 실패로 확정됩니다.
- 완료: 스캔이 끝난 항목입니다.
- 이미 반영됨: 스캔은 끝났지만 새로 등록된 것이 없는 항목입니다. 이미 shyni에 반영돼 있던 내용입니다.
- 메타 정보 없음: 완료됐지만 앨범 정보를 불러오지 못한 항목에 표시됩니다. 대상이 CD1 같은 앨범 아래 하위 폴더이면 그 이유가 함께 표시됩니다.
- 실패: 스캔이 실패로 끝난 항목입니다. 사유에 따라 아래로 나뉩니다.
    - 분석시간 초과: 스캔이 시작된 뒤 스캔 설정의 analyze 후 대기 시간 이상 끝나지 않아 실패로 표시한 항목입니다. 분석 자체가 실패한 것이 아니라 설정한 시간이 지난 것입니다. shyni 작업은 계속 돌고 있을 수 있고, 뒤늦게 끝나면 이력에 스캔완료가 이어서 표시됩니다. 상태는 실패로 남으니, 다시 처리하려면 리셋해 주세요.
    - 스캔 실패: shyni 스캔 작업(job) 자체가 실패로 끝났습니다.
    - 전송 오류: 스캔을 보내는 단계(라이브러리 조회·스캔 전송)에서 시간 초과나 연결 실패가 생긴 항목입니다. 일시적인 오류는 실패로 확정하지 않고 다음 주기에 다시 보내며, 연속 5회 실패하면 실패로 확정하고 사유를 함께 표시합니다.
    - 라이브러리 없음: 항목 경로에 맞는 shyni 라이브러리를 찾지 못했습니다.
    - 항목 없음: 라이브러리는 찾았지만 그 안에서 항목을 찾지 못했습니다.

### rclone vfs/refresh 연동

스캔 경로가 규칙에 매칭되면 rc addr에 호출하여 vfs/refresh를 수행합니다.

* 규칙 형식: `{로컬 경로}|{리모트 경로}|{rc 주소}#{VFS 이름}|{user}|{pass}` (user/pass·#VFS는 옵션)
* 대상의 부모부터 OK를 받을 때까지 상위로 올라가며 새로고침한 뒤, 대상 폴더를 recursive로 새로고침합니다.
* rclone 플러그인이 설치되어 있어야 합니다 (rclone 실행 파일 경로를 그 설정에서 읽습니다).

### 휴지통

shyni 스캔에서 찾지 못한 파일은 휴지통으로 표시됩니다 (shyni 데이터베이스 기준).

- 대시보드의 라이브러리 카드 '휴지통' 버튼: 비우기와 휴지통 상세 중 하나를 고릅니다.
  비우기를 고르면 동작(새로고침 · 스캔 · 비우기 · 새로고침 후 스캔 · 새로고침 후 스캔 후 비우기)을 골라 실행합니다.
- 스캔 > 휴지통 조회: 라이브러리를 골라 작품 단위로 묶어 보여 줍니다. 제목·경로 검색, 정렬, 페이지 이동이 되고,
  항목마다 삭제된 날짜와 보관 기간을 표시합니다. 보관 기간은 shyni 서버가 관리합니다.
    - 조회한 작품을 골라 새로고침 · 스캔 · 새로고침 후 스캔을 실행할 수 있고, 전체 비우기도 할 수 있습니다.
    - 상세 조회는 Relay(PostgreSQL Relay) 연결이 필요합니다. 조회에 시간이 걸릴 수 있어 한 번 불러온
      결과는 저장해 두고, 다음에는 캐시 데이터로 바로 보여 줍니다. 최신 상태는 '최신으로 조회'로
      다시 불러옵니다.
- 휴지통 작업(상단 메뉴): 이름 · 실행 주기(cron) · 대상 라이브러리 · 동작을 정해 두면 주기적으로 휴지통을 처리합니다.
- 주기적 스캔과 휴지통 작업의 실행 이력은 30개 단위 목록으로 볼 수 있고, 오래된 이력은 각
  설정에서 정한 삭제 기간(기본값 30일) 기준으로 지웁니다. 자동 삭제를 켜 두면 기간이 지난
  이력이 자동으로 삭제됩니다.

### 웹훅 (Discord 중계)

shyni 웹훅을 SHYNI MATE가 대신 받아 Discord로 보기 좋게 바꿔 보냅니다.

- 웹훅 메뉴에서 Discord 중계 사용 여부와 Discord 웹훅 주소를 설정합니다.
  '수신 주소' 탭에 표시되는 주소를 shyni의 웹훅 목록에 등록하세요.
- 신규 항목은 5분간 모아서 라이브러리별 요약으로 보냅니다 (앨범 수 · 트랙 수, 표지 이미지 포함).
- 재생 알림은 받을 이벤트(재생 · 일시정지 · 이어 재생 · 정지 · 재생 완료)를 골라 받을 수 있고,
  라이브러리명 · 제목 · 앨범 · 재생 방식 · 재생 기기를 한 줄씩 표시합니다. 표지 이미지도 함께 표시됩니다.

### 설정

- 기본 설정: shyni 주소 / shyni 토큰 (연결 테스트 버튼으로 라이브러리 조회 확인 가능),
  휴지통 개수 자동 갱신 주기(기본값 12시간 — 대시보드·건강도의 휴지통 개수를 매번 읽지 않고 저장해 둔 값을 쓰는 주기)
- 설정의 Relay 메뉴: PostgreSQL Relay 연결 정보와 연결 테스트. 연결되면 대시보드 · 건강도의 미디어 수와
  휴지통 상세를 데이터베이스 기준으로 보여 줍니다. 설치 방법은 Relay 화면의 'Relay 매뉴얼' 탭을 참고하세요.
- 스캔 설정: 동시 스캔 수(기본값 2), 스캔 대기 시간(기본값 5분), 반영 여부 확인 제한 시간(기본값 60초),
  analyze 대기 시간(기본값 5분), analyze 후 대기 시간(기본값 60분), 파일체크 주기(기본값 60초),
  VFS 새로고침 사용 여부와 규칙, 샤이니 경로 매핑, 디스크가 바쁠 때 스캔 양보, DB 자동 삭제
- 스캔 설정의 고급 설정 탭 — 조회 15초 · 전송 30초 · 작업 확인 15초 · 콜백 10초 · VFS 새로고침 600초가 기본값입니다.
  평소에는 입력 칸이 잠겨 있고, '활성화'에 체크해야 값을 바꿀 수 있습니다.
  응답이 이 시간보다 늦으면 실패로 단정하지 않고 다음 주기에 다시 시도합니다. shyni가 재시작 중이면 작업 확인은
  연결 오류 연속 3회에서 그 주기를 중단하고 다음 주기에 재개하며, 복구 후 첫 주기는 analyze 시간 초과 실패 확정을 미룹니다.
