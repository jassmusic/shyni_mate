스캔 매뉴얼

SHYNI SCAN 동작 방식 상태 의미 완료와 라이브러리 등록 리셋과 재시도 rclone vfs/refresh 연동 휴지통 웹훅 (Discord 중계) 설정 화면 갱신

SHYNI SCAN

수신된 항목을 shyni 서버로 처리합니다. 항목마다 VFS 새로고침 → 스캔 전송 → 결과 확인 순서로 진행하고, 동시에 처리하는 항목 수는 동시 스캔 수(기본 2개)까지입니다.

  • 동시에 실행 중인 스캔 수는 스캔 설정의 동시 스캔 수(기본 2)로 제한합니다. 수신이 한꺼번에 몰려도 shyni에 한 번에 보내지 않습니다.
  • 라이브러리 단위 스캔(대시보드 카드·주기적 스캔·휴지통 스캔)은 기본 설정 스캔 전역 설정 탭의 라이브러리 동시 스캔 수(기본 2)로 따로 제한합니다. 스캔이 들어간 작업은 경로와 상관없이 1건으로 세고, 상한에 걸리거나 같은 라이브러리가 스캔 중이면 스케줄 작업은 자리가 날 때까지 기다리고, 수동 실행은 바로 거절됩니다. 자세한 내용은 주기적 스캔 매뉴얼과 휴지통 매뉴얼을 봐 주세요.
  • MODE
    • ADD : 신규 항목 스캔 (전송 전 VFS 새로고침)
    • REMOVE_FILE / REMOVE_FOLDER : 삭제 스캔
    • REFRESH : 해당 경로의 메타데이터 새로고침. 항목이 아직 없으면 먼저 등록 스캔 후 새로고침합니다.
  • API로 스캔을 보낼 수도 있습니다. 주소는 /shyni_mate/api/scan/do_scan입니다.
    • target: 스캔할 경로입니다.
    • mode: 동작 방식입니다. 안 적으면 ADD(신규 스캔)로 처리합니다.
    • target_section_id: 대상 라이브러리 번호입니다. 안 적으면 경로에서 찾습니다.
    • callback_id·callback_url: 스캔이 끝나면 결과를 알려 받을 주소입니다. 안 적어도 됩니다.
    • apikey: API 키입니다. 반드시 적어야 합니다.
  • VFS 새로고침만 따로 보낼 수도 있습니다. /shyni_mate/api/scan/vfs_refresh에 경로(target)를 보내면, 스캔 없이 해당 경로의 디렉터리 정보만 새로 읽습니다. 하위 폴더까지 새로고침하려면 recursive, 끝날 때까지 기다리지 않으려면 async를 함께 보냅니다.
  • 메타데이터 새로고침도 API로 보낼 수 있습니다. /shyni_mate/api/scan/manual_refresh에 작품 번호(metadata_item_id)를 보내면, 해당 작품의 메타데이터만 다시 불러옵니다.

동작 방식

  1. 파일체크 주기(기본 60초)마다 READY 항목을 오래된 순으로 확인합니다.
  2. 실행 중인 shyni job이 동시 스캔 수 미만일 때만 다음 항목을 전송합니다.
    • ADD: 설정이 켜져 있으면 먼저 rclone RC로 대상 경로를 VFS 새로고침(recursive)합니다. VFS 새로고침 사용은 기본적으로 꺼져 있습니다.
    • 경로를 shyni 경로 매핑 규칙으로 변환한 뒤, /compat/section_by_path로 섹션을 찾고 POST /library/sections/{id}/refresh로 부분 스캔을 전송합니다.
    • GDS 수신 원문에 ffprobe 자료가 있으면 함께 전달해 shyni가 분석을 건너뛰게 합니다.
    • 디스크 대기가 임계값(기본 40%) 이상이면 새 전송을 한 주기 미룹니다 (스캔 설정의 '디스크가 바쁠 때 스캔 양보', 기본 켜짐). 이미 전송된 항목의 확인은 계속됩니다.
    • 스왑 사용량이 임계값(기본 2048MB) 이상이면 새 전송을 한 주기 미룹니다 (스캔 설정의 '메모리가 부족할 때 스캔 양보', 기본 꺼짐). 이미 전송된 항목의 확인은 계속됩니다.
  3. 전송된 job은 매 주기 /compat/jobs/{job_id}로 폴링해 완료/실패를 확정합니다.
  4. 완료되면 항목이 FINISH_SHYNI가 되고, 등록된 callback으로 결과를 통지합니다.

상태 의미

스캔 목록의 상태 필터와 항목에 표시되는 상태입니다.

  • 준비중: 아직 shyni에 보내지 않은 항목입니다. 파일체크 주기마다 오래된 순으로 처리되고, 설정된 스캔 수에 맞춰 전송됩니다.
  • 보류: Shyni 연동이 꺼져 있는 동안 쌓인 항목입니다. 연동을 켜도 자동으로 처리되지 않으며, 목록에서 보류 해제를 해야 처리가 시작됩니다.
  • ffprobe 대기 중: 파일이 많은 항목은 ffprobe 데이터가 여러 개로 나뉘어 전송됩니다. shyni에 보냈지만 아직 데이터가 다 모이지 않은 상태로, 옆에 (받은 수/전체 수)가 표시됩니다. 30분이 지나도 전체 데이터가 모이지 않을 경우, shyni가 받은 데이터만으로 스캔을 진행합니다.
  • 스캔 대기 중: ffprobe 데이터는 다 모였지만 shyni가 아직 스캔을 시작하지 않은 상태입니다. 스캔 작업이 등록만 되고 차례를 기다리는 경우도 포함됩니다.
  • 진행중: shyni가 지금 이 항목을 스캔하고 있는 상태입니다.
  • 분석중: 전송 후 analyze 단계에서 스캔 설정의 analyze 대기 시간 이상 머물고 있는 항목입니다. 동시 스캔 수에서는 제외되며, shyni가 스캔을 끝내면 정상적으로 완료 처리됩니다. 단, analyze 후 대기 시간까지 끝나지 않으면 실패로 확정됩니다.
  • 완료: 스캔이 끝난 항목입니다.
  • 이미 반영됨: 스캔은 끝났지만 새로 등록된 것이 없는 항목입니다. 이미 shyni에 반영돼 있던 내용입니다.
  • 메타 정보 없음: 완료됐지만 앨범 정보를 불러오지 못한 항목에 표시됩니다. 대상이 CD1 같은 앨범 아래 하위 폴더이면 그 이유가 함께 표시됩니다.
  • 실패: 스캔이 실패로 끝난 항목입니다. 사유에 따라 아래로 나뉩니다.
    • 분석시간 초과: 스캔이 시작된 뒤 스캔 설정의 analyze 후 대기 시간 이상 끝나지 않아 실패로 표시한 항목입니다. 분석 자체가 실패한 것이 아니라 설정한 시간이 지난 것입니다. shyni 작업은 계속 돌고 있을 수 있고, 뒤늦게 끝나면 이력에 스캔완료가 이어서 표시됩니다. 상태는 실패로 남으니, 다시 처리하려면 리셋해 주세요.
    • 스캔 실패: shyni 스캔 작업(job) 자체가 실패로 끝났습니다.
    • 전송 오류: 스캔을 보내는 단계(라이브러리 조회·스캔 전송)에서 시간 초과나 연결 실패가 생긴 항목입니다. 일시적인 오류는 실패로 확정하지 않고 다음 주기에 다시 보내며, 연속 5회 실패하면 실패로 확정하고 사유를 함께 표시합니다.
    • 라이브러리 없음: 항목 경로에 맞는 shyni 라이브러리를 찾지 못했습니다.
    • 항목 없음: 라이브러리는 찾았지만 그 안에서 항목을 찾지 못했습니다.

완료와 라이브러리 등록

스캔이 완료됐다고 해서 앨범이 라이브러리에 등록된 것은 아닙니다. shyni가 스캔 작업을 끝냈다고 답하면 메이트는 완료로 처리하지만, 등록은 별개입니다.

스캔은 끝났는데 파일이 없거나 메타 추출이 안 돼서 등록이 안 될 수 있습니다. 이런 경우 완료 건수와 라이브러리 실제 앨범 수가 맞지 않습니다.

메이트는 완료 처리할 때 경로로 앨범을 한 번 더 조회합니다. 못 찾으면 목록에 '메타 정보 없음'으로 표시합니다. 그래도 상태는 완료로 찍힙니다.

빠진 앨범을 채우려면 주기적 스캔을 돌리면 됩니다. 주기적 스캔은 라이브러리 전체를 훑어서 디스크에 있는데 라이브러리에 없는 앨범을 찾아 등록합니다.

리셋과 재시도

실패한 항목을 다시 처리하려면 리셋하거나 재시도합니다.

  • 리셋: 항목을 처음 받은 상태로 되돌립니다. 스캔 기록·VFS 완료 여부·메타 정보가 전부 지워지고, 파일체크부터 다시 시작합니다. Shyni 연동이 꺼져 있어도 리셋한 항목은 전송됩니다.
  • 재시도: 항목을 READY 상태로 되돌립니다. 리셋보다 가볍고, 기존 기록은 유지됩니다.

목록에서 항목을 골라 리셋·재시도를 실행할 수 있습니다. 실행 중인 항목은 건너뜁니다.

rclone vfs/refresh 연동

스캔 경로가 규칙에 맞으면 rclone RC에 vfs/refresh를 요청합니다.

  • 규칙 형식: {로컬 경로}|{리모트 경로}|{rc 주소}#{VFS 이름}|{user}|{pass} (user/pass·#VFS는 옵션)
  • 대상의 부모부터 OK를 받을 때까지 상위로 올라가며 새로고침한 뒤, 대상 폴더를 recursive로 새로고침합니다.
  • rclone 플러그인이 설치되어 있어야 합니다 (rclone 실행 파일 경로를 그 설정에서 읽습니다).

휴지통

shyni 스캔에서 찾지 못한 파일은 '못 찾음' 상태로 표시됩니다 (shyni 데이터베이스 기준). 아직 휴지통이 아니라, 비우기를 실행해야 휴지통으로 넘어갑니다. 자세한 과정은 휴지통 매뉴얼의 '휴지통 비우기, 어떻게 처리되나' 절을 봐 주세요.

  • 대시보드의 라이브러리 카드 '휴지통' 버튼: 비우기와 휴지통 상세 중 하나를 고릅니다. 비우기를 고르면 동작(새로고침 · 스캔 · 비우기 · 새로고침 후 스캔 · 새로고침 후 스캔 후 비우기)을 골라 실행합니다.
  • 휴지통 스캔 > 휴지통: 라이브러리를 골라 작품 단위로 묶어 보여 줍니다. 제목·경로 검색, 정렬, 페이지 이동이 되고, 항목마다 삭제된 날짜와 보관 기간을 표시합니다. 보관 기간은 shyni 서버가 관리합니다.
    • 조회한 작품을 골라 새로고침 · 스캔 · 새로고침 후 스캔을 실행할 수 있고, 전체 비우기도 할 수 있습니다.
    • 상세 조회는 Relay(PostgreSQL Relay) 연결이 필요합니다. 조회에 시간이 걸릴 수 있어 한 번 불러온 결과는 저장해 두고, 다음에는 캐시 데이터로 바로 보여 줍니다. 최신 상태는 '최신으로 조회'로 다시 불러옵니다.
  • 휴지통 스캔(상단 메뉴): 이름 · 실행 주기(cron) · 대상 라이브러리 · 동작을 정해 두면 주기적으로 휴지통을 처리합니다.
  • 주기적 스캔과 휴지통 스캔의 실행 이력은 30개 단위 목록으로 볼 수 있고, 오래된 이력은 각 설정에서 정한 삭제 기간(기본값 30일) 기준으로 지웁니다. 자동 삭제를 켜 두면 기간이 지난 이력이 자동으로 삭제됩니다.

웹훅 (Discord 중계)

shyni 웹훅을 SHYNI MATE가 대신 받아 Discord로 보기 좋게 바꿔 보냅니다.

  • 웹훅 메뉴에서 Discord 중계 사용 여부와 Discord 웹훅 주소를 설정합니다. '수신 주소' 탭에 표시되는 주소를 shyni의 웹훅 목록에 등록하세요.
  • 신규 항목은 바로 보내지 않고 모았다가, 마지막으로 새 항목이 들어온 뒤 5분이 지나면 라이브러리별 요약으로 보냅니다 (앨범 수 · 트랙 수, 표지 이미지 포함). 모으는 간격은 웹훅 설정의 '신규 항목 묶는 간격'(기본 5분)에서 바꿀 수 있습니다.
  • 재생 알림은 받을 이벤트(재생 · 일시정지 · 이어 재생 · 정지 · 재생 완료)를 골라 받을 수 있고, 라이브러리명 · 제목 · 앨범 · 재생 방식 · 재생 기기를 한 줄씩 표시합니다. 표지 이미지도 함께 표시됩니다.

설정

기본 설정

  • shyni 주소와 shyni 토큰을 적습니다. 연결 테스트 버튼으로 라이브러리 조회가 되는지 확인할 수 있습니다.
  • 스캔 전역 설정 탭의 라이브러리 동시 스캔 수(기본값 2)는 라이브러리 단위 스캔(대시보드 카드·주기적 스캔·휴지통 스캔)이 동시에 몇 개까지 도는지 정합니다.
  • 스캔 전역 설정 탭의 파일 대기 시간(기본값 5분): 파일이 아직 마운트에 보이지 않을 때, shyni 서버가 이 시간만큼 기다리도록 전달하는 값입니다. 메이트가 기다리는 시간이 아니라 shyni에 전달하는 값입니다.
  • 휴지통 개수 자동 갱신 주기(기본값 12시간)는 휴지통 스캔 → 휴지통 페이지 우측 상단에서 바꿀 수 있습니다. 대시보드·건강도의 휴지통 개수를 매번 읽지 않고 저장해 둔 값을 쓰는 주기입니다.
  • 설정의 Relay 메뉴에서 PostgreSQL Relay 연결 정보와 연결 테스트를 합니다. 연결되면 대시보드 · 건강도의 미디어 수와 휴지통 상세를 shyni 데이터베이스 기준으로 보여 줍니다. 설치 방법은 Relay 화면의 'Relay 매뉴얼' 탭을 참고하세요.

스캔 설정

  • 동시 스캔 수(기본값 2): 한 번에 shyni로 전송해 동시에 실행할 스캔 수입니다.
  • 파일체크 주기(기본값 60초): 새로 들어온 항목이 있는지 확인하는 간격입니다.
  • analyze 대기 시간(기본값 5분): 스캔 중 상태로 이 시간 이상 머물러 있는 항목은 정체로 보고 동시 스캔 수에서 제외합니다. 제외된 항목은 '분석중'으로 표시되고, shyni가 스캔을 끝내면 정상적으로 완료 처리됩니다. 파일 대기 시간과는 별개 설정입니다.
  • analyze 후 대기 시간(기본값 60분): 스캔이 시작된 뒤 이 시간 이상 끝나지 않는 항목은 실패로 확정합니다.
  • rclone vfs/refresh 사용(기본 꺼짐): 켜면 스캔을 보내기 전에 rclone으로 대상 경로를 새로고침합니다. 규칙은 기본 설정의 스캔 전역 설정에서 정합니다.
  • VFS 비동기 사용(기본 켜짐): 켜면 새로고침 작업을 걸어 두고 완료를 확인하면서 기다리고, 끄면 새로고침이 끝날 때까지 기다리는 동기 방식으로 진행합니다. 비동기 방식으로 새로고침이 반복해서 실패하면, 끄고 동기 방식으로 사용해 보세요.
  • Shyni 연동 사용: 끄면 준비 중인 항목은 보류가 됩니다. 다시 켜도 자동으로 처리되지 않으니, 스캔 목록에서 보류를 해제해 주세요.
  • shyni 경로 매핑: 받은 경로를 shyni가 보는 경로로 바꾸는 규칙으로, 기본 설정의 스캔 전역 설정에서 정합니다.
  • 디스크가 바쁠 때 스캔 양보(기본 켜짐): 디스크 대기가 임계값(기본 40%) 이상이면 새 스캔 전송을 한 주기 미룹니다. 이미 전송된 스캔의 확인은 계속됩니다.
  • 메모리가 부족할 때 스캔 양보(기본 꺼짐): 스왑 사용량이 임계값(기본 2048MB) 이상이면 새 스캔 전송을 한 주기 미룹니다. 이미 전송된 스캔의 확인은 계속됩니다.
  • 반영 여부 확인 제한 시간(기본값 60초): 리셋한 항목을 다시 처리할 때, 이미 라이브러리에 반영돼 있는지 shyni에 확인하는 조회가 끝날 때까지 기다리는 최대 시간입니다. 일반 항목은 확인 없이 바로 전송합니다.
  • 진행 중 표시 정리 시간(기본값 30분): 대시보드에서 진행 중으로 보이지만 끝났는지 확인할 방법이 없는 상태가 이 시간 이상 계속되면, 진행 중 표시를 중단됨으로 정리합니다. 정리하는 것은 화면 표시뿐이고, shyni에서 실제 작업이 계속 돌고 있다면 멈추지 않습니다.
  • DB 자동 삭제: 켜 두면, 설정한 기간이 지난 DB 기록을 자동으로 삭제합니다.

스캔 설정의 고급 설정 탭

조회 15초 · 전송 30초 · 작업 확인 15초 · 콜백 10초 · VFS 새로고침 600초가 기본값입니다. 평소에는 입력 칸이 잠겨 있고, '활성화'에 체크해야 값을 바꿀 수 있습니다. 응답이 이 시간보다 늦으면 실패로 단정하지 않고 다음 주기에 다시 시도합니다. shyni가 재시작 중이면 작업 확인은 연결 오류 연속 3회에서 그 주기를 중단하고 다음 주기에 재개하며, 복구 후 첫 주기는 analyze 시간 초과 실패 확정을 미룹니다.

화면 갱신

각 화면은 갱신 방식이 다릅니다. 어떤 화면은 자동으로 바뀌고, 어떤 화면은 새로고침 버튼을 눌러야 바뀝니다.

대시보드

  • 대시보드는 미리 만들어 둔 목록을 보여 줍니다. 기본적으로 최대 30분 된 복사본이 보일 수 있습니다. 화면 상단의 "불러오기 완료 · N분 전"이 복사본 기준 시각입니다.
  • 전체 목록은 30분마다 자동으로 다시 불러옵니다. 주기는 설정의 '자동 업데이트 주기'(기본 30분, 0~120분)에서 바꿀 수 있고, 0으로 두면 자동 갱신이 안 됩니다.
  • 각 라이브러리의 작업 상태 줄은 30초마다 갱신됩니다. 진행 중인지, 끝났는지는 비교적 실시간에 가깝게 보입니다.
  • DB 통계(파일 수·메타 없음·휴지통 수 등)는 최대 6시간까지 낡을 수 있습니다. 최신 수치가 필요하면 새로고침 버튼을 눌러 주세요.
  • 데이터 용량은 자동으로 측정하지 않습니다. 새로고침 아이콘을 눌렀을 때만 측정합니다.

건강도

  • 건강도는 대시보드와 같은 자동 업데이트 주기(기본 30분)로 다시 불러옵니다.
  • 건강도 수치는 DB 통계에서 오므로 최대 6시간까지 낡을 수 있습니다. 페이지를 여는 것만으로는 다시 계산하지 않습니다.

세션

  • 세션 목록은 매번 데이터베이스에서 직접 조회하므로, 불러온 순간의 실시간 값입니다.
  • 다만 자동 업데이트 주기가 30분이라, 페이지를 열어둔 채로는 최대 30분 동안 로그인·로그아웃이 반영되지 않습니다. 바로 확인하려면 새로고침 버튼을 눌러 주세요.

스캔 목록

  • 스캔 목록은 자동으로 바뀌지 않습니다. 필터를 바꾸거나, 정렬·검색을 하거나, 페이지를 이동하거나, 새로고침 버튼을 눌러야 최신 상태가 보입니다.
  • 목록 위의 진행현황 한 줄(분석중·진행중·대기·준비중·보류·완료·실패 개수)은 파일체크 워커가 60초 주기마다 갱신해 둔 값을 보여 줍니다. 최대 60초 이상 낡을 수 있습니다.
  • "(N초 전)" 숫자는 1초마다 올라가지만, 글자만 바뀌는 것이고 데이터가 새로워지는 게 아닙니다.
