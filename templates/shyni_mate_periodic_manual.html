작업 관리

라이브러리를 골라 cron으로 등록해 두면, 정해진 시각에 하나씩 순차로 실행합니다. 동작은 새로고침·스캔·새로고침 후 스캔 중에서 고를 수 있습니다.

작업 결과

주기적 스캔의 실행 결과를 봅니다. 행을 누르면 단계별 소요와 집계, 추가된 파일을 볼 수 있습니다. 대시보드에서 누른 스캔·새로고침도 여기에 '대시보드 (수동)' 작업으로 남습니다. 행 상세에는 rclone job id(동기 방식일 때는 rclone process id)와 shyni 스캔 작업 번호도 표시됩니다.

설정

주기적 스캔의 VFS 새로고침 제한 시간, VFS 비동기 사용, 작업 대기 시간, 스캔 대기 시간, 진행 중 표시 정리 시간과 실행 이력 보관 기간을 정합니다.

VFS 새로고침 제한 시간은 라이브러리 새로고침이 끝나기를 기다리는 시간입니다. 기본값은 360분(6시간)이고, 이 시간을 넘겨도 새로고침이 끝나지 않으면 그 라이브러리는 실패로 끝나고 스캔은 보내지 않습니다. 새로고침 자체는 rclone 쪽에서 계속 돌 수 있습니다. 대시보드에서 누른 새로고침·새로고침 후 스캔도 이 시간을 따릅니다.

VFS 비동기 사용(기본 켜짐)은 새로고침을 거는 방식입니다. 켜면 새로고침 작업을 걸어 두고 완료를 확인하면서 기다리고, 끄면 새로고침이 끝날 때까지 기다리는 동기 방식으로 진행합니다. 비동기 방식으로 새로고침이 반복해서 실패하면, 끄고 동기 방식으로 사용해 보세요.

스캔 대기 시간은 shyni 스캔이 끝나기를 기다리는 시간입니다. 기본값은 360분(6시간)이고, 시간이 다 돼도 스캔이 진행 중이면 시간을 연장해 계속 기다리지만, 스캔이 멈췄다고 판단되면(대기 시간 내내 진행 확인이 안 되면) 실패로 끝냅니다.

진행 중 표시 정리 시간은 진행 중 표시가 이 시간 이상 그대로면 정리하는 시간입니다. 기본값은 30분입니다. 실행 이력 보관 기간은 작업 결과 이력을 얼마나 오래 두는지 정합니다. 기본값은 30일이고, 기간이 지난 이력은 자동으로 삭제됩니다.

작업이 겹치면 기다립니다

주기적 스캔 작업은 아래 두 가지 제한 안에서 함께 돌 수 있습니다. 정해진 시각에 자리가 없으면 실패하지 않고, 자리가 날 때까지 기다렸다가 이어서 실행합니다. 기다리는 동안 작업 관리·작업 결과 목록에 '대기중' 카드가 나오고, 작업 결과에는 '대기 중' 행이 생겨 앞선 작업 이름과 기다린 시간이 표시됩니다. 같은 작업이 이미 돌거나 기다리고 있으면 중복으로 실행하지 않습니다. 작업 대기 시간은 설정에서 정합니다. 기본값은 360분(6시간)이고, 0으로 두면 기다리지 않고 바로 실패로 끝납니다.

시작할 때는 두 가지 제한을 순서대로 봅니다. 먼저 같은 모듈 안에서 같은 라이브러리가 이미 작업 중이면 동작 종류와 무관하게 시작하지 않습니다(규칙 1). 다음으로 스캔이 들어간 동작은 다른 라이브러리 스캔이 상한까지 돌고 있어도 시작하지 않습니다(규칙 2). 상한은 기본 설정 스캔 전역 설정의 '라이브러리 동시 스캔 수'(기본 2)입니다. 규칙 1이 규칙 2보다 먼저 적용됩니다. 대기 중인 작업도 자리로 셉니다 — 같은 작업이 이미 대기 중이면 또 쌓지 않고 '이미 대기 중입니다'라고 거절하고, 대기 중인 스캔이 있으면 그 자리까지 합쳐서 상한을 봅니다.

실행 중인 작업이 많아 워커가 바쁠 때는, 보낸 작업이 바로 시작하지 않고 대기열에 쌓입니다. 이때도 작업 관리·작업 결과 목록에 '대기 중' 카드와 행이 나와서, 어떤 작업이 기다리고 있는지 볼 수 있습니다. 워커 자리가 나면 순서대로 시작됩니다. 6시간이 지나도 시작하지 못하면 대기 항목은 사라지고 로그에 남습니다.

휴지통 스캔과는 따로 돕니다

주기적 스캔과 휴지통 스캔은 줄이 따로입니다. 주기적 스캔이 도는 중에도 휴지통 스캔은 기다리지 않고 바로 시작하고, 반대도 마찬가지입니다. 다만 같은 라이브러리는 두 작업이 동시에 건드리지 않습니다. 휴지통 스캔 중인 라이브러리는 주기적 스캔에서 건너뛰고 다음 라이브러리로 넘어갑니다.

휴지통 스캔뿐 아니라, 대시보드에서 시작한 VFS 새로고침·스캔·메타 새로고침·휴지통 비우기가 같은 라이브러리에서 돌고 있어도 건너뛰고 다음 라이브러리로 넘어갑니다. 휴지통 스캔 상태를 확인할 수 없을 때도 안전을 위해 건너뜁니다.

지금 실행은 라이브러리 자리를 기다리지 않습니다

'지금 실행'은 수동 실행이라 라이브러리 자리가 없으면 기다리지 않고 바로 거절됩니다. 같은 라이브러리가 이미 작업 중이면 동작 종류와 무관하게 거절되고, 스캔이 들어간 동작은 다른 라이브러리 스캔이 설정한 개수까지 돌고 있어도 거절됩니다. 다만 실행 중인 작업이 많아 워커가 바쁠 때는 대기열에 쌓여 '대기 중'으로 표시되고, 워커 자리가 나면 순서대로 시작됩니다. 돌고 있는 작업 행의 버튼은 [취소]로 바뀌어 있으니, 멈추려면 취소를 눌러 주세요.

취소

돌고 있는 작업은 작업 관리·작업 결과 화면의 [취소] 버튼으로 멈출 수 있습니다. 버튼을 누르면 확인 창이 나오고, 확인하면 취소가 진행됩니다.

  • 대기 중인 작업은 대기 줄에서 빠집니다. 워커 대기열에 쌓인 작업을 취소하면 이력에 '대기가 취소되었습니다' 행이 남습니다.
  • VFS 새로고침 단계에서는 새로고침이 끝나기를 기다리는 것을 멈추고, rclone에 새로고침 중단도 요청합니다. 다만 rclone이 바로 멈추지 않을 수 있어, 새로고침 자체는 백그라운드에서 끝까지 돌 수 있습니다.
  • 스캔 단계에서는 shyni에 스캔 취소를 요청합니다. shyni에서 실행 중인 스캔은 취소 요청이 닿지 않아 계속될 수 있으니, 멈췄는지 확인하고 싶으면 shyni 웹에서 직접 확인해 주세요.

취소는 지금 실행 중인 단위 하나만 멈춥니다. 대기 중인 다른 단위는 건드리지 않습니다.

FF 재시작 시 복구

FF가 재시작되면, 실행 중이던 주기적 스캔은 다시 시작할 때 이어서 확인합니다. 스캔 단계에서 멈춘 항목은 shyni 스캔이 끝났는지 이어서 확인하고, VFS 단계에서 멈춘 항목은 rclone 새로고침을 다시 물어봅니다.

VFS 단계 복구는 새로고침 작업 번호로 rclone에 물어봅니다.

  • 작업 번호가 없으면 처음부터 다시 새로고침합니다.
  • 작업 번호가 있는데 rclone에 기록이 없으면 처음부터 다시 새로고침합니다.
  • 새로고침이 아직 진행 중이면 그 작업을 이어서 기다립니다.
  • 새로고침이 끝났으면 완료로 기록하고 스캔으로 넘어갑니다. 끝났는데 오류가 있었으면 처음부터 다시 새로고침합니다.

복구가 끝난 뒤에는 같은 작업의 남은 라이브러리도 이어서 스캔합니다.

화면 갱신

작업 관리·작업 결과 화면

  • 진행 중 카드는 15초마다 자동으로 갱신됩니다. 단계·진행률·경과 시간이 바뀝니다.
  • '지금 실행'을 누른 뒤에는 3초 간격으로 빠르게 갱신합니다 (90초 동안, 실제 카드가 뜨면 그 전에 끝납니다).
  • 작업 정의(이름·실행 주기·대상 라이브러리)는 자동으로 바뀌지 않습니다. 다른 화면에서 바꾼 내용은 페이지를 다시 불러와야 보입니다.
  • 작업 결과의 이력 목록은 스캔이 진행되는 동안 자동으로 바뀌지 않습니다. 스캔이 끝나면 진행 카드가 사라지면서 목록이 자동으로 다시 불러와져 '완료'와 집계가 반영됩니다. 그 전에 최신 상태를 보고 싶으면 새로고침 버튼을 눌러 주세요.

메이트가 shyni·rclone과 주고받는 주기

  • VFS 새로고침 확인은 10초마다 rclone에 물어봅니다.
  • 스캔 완료 확인은 20초마다 shyni에 물어봅니다.
  • 대기 확인은 10초마다 합니다.
  • 스캔 진행률은 60초마다 기록합니다. 그래서 브라우저가 15초마다 물어도, 진행률 숫자 자체는 최대 60초마다만 바뀝니다.
