왜 설정하나요?
shyni 안쪽을 살짝 들여다보기 위한 연결입니다. 평소 주고받는 토큰 연동만으로는 알 수 없는 것들, 예를 들어 라이브러리에 미디어가 몇 개나 있는지 같은 정보를 데이터베이스에서 직접 읽어 오기 위한 것입니다.
무엇을 볼 수 있나요?
대시보드 화면에서 라이브러리마다 미디어 수, 항목 수, 메타가 없는 수를 볼 수 있습니다. 라이브러리가 잘 채워져 있는지 한눈에 확인하는 데 쓰입니다.
안전할까요?
읽는 것만 되는 계정을 쓰기 때문에, 이 연결로는 데이터를 바꾸거나 지울 수 없습니다. 혹시 모를 일을 막기 위해 꼭 읽기 전용 계정만 적어 주세요. 그리고 연결 테스트를 통과한 설정만 사용합니다. 값을 하나라도 바꾸면, 다시 연결 테스트를 통과하기 전까지는 데이터베이스 정보를 활용하지 않습니다.

이 플러그인은 대시보드 화면의 미디어 수·항목 수·메타 없음 수와 건강도 통계를 shyni 데이터베이스에서 직접 읽어 보여 줍니다. 그러려면 데이터베이스에 읽기로 접속할 수 있어야 하는데, shyni의 PostgreSQL은 기본 설정으로는 다른 프로그램의 접속을 받지 않는 경우가 많아 중계(Relay)가 필요할 수 있습니다. 아래 순서대로 따라 하시면 됩니다. 먼저 공통 준비로 읽기 전용 계정을 만들고, 본인의 설치 형태(Docker / 직접 설치)에 맞는 절을 진행하세요.

공통 준비 — 읽기 전용 계정 만들기

1. shyni의 PostgreSQL에 관리자로 접속합니다.
· Docker: docker exec -it <shyni 컨테이너 이름> psql -U shyni -d shyni
· 직접 설치: psql -U shyni -d shyni (설치 환경에 따라 명령이 다를 수 있습니다)
2. 아래 SQL을 실행합니다. 비밀번호 부분은 직접 정한 값으로 바꾸세요. 

CREATE ROLE shyni_ro LOGIN PASSWORD '비밀번호';
GRANT CONNECT ON DATABASE shyni TO shyni_ro;
GRANT USAGE ON SCHEMA public TO shyni_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO shyni_ro;
ALTER DEFAULT PRIVILEGES FOR ROLE shyni GRANT SELECT ON TABLES TO shyni_ro;
ALTER ROLE shyni_ro SET default_transaction_read_only = on;

3. 만든 비밀번호는 Relay 설정에 입력해야 하니 따로 적어 두세요. 이 계정은 조회(SELECT)만 되고, 수정·삭제는 데이터베이스 차원에서 거부됩니다.

Docker로 설치한 경우

shyni 컨테이너의 PostgreSQL은 컨테이너 안쪽(127.0.0.1)에서만 접속을 받고, 포트도 밖으로 열려 있지 않습니다. 그래서 socat 중계 컨테이너 두 개로 길을 만듭니다.
· pgrelay_in: shyni 컨테이너와 네트워크를 공유해 127.0.0.1:5432에 닿는 중계
· pgrelay_out: shyni 쪽 네트워크와, 이 플러그인이 실행되는 컨테이너(ff) 쪽 네트워크에 함께 붙어 양쪽을 이어 주는 중계

1. shyni의 docker-compose에 두 서비스를 추가합니다. shyni 서비스 이름이 다르면 본인 이름으로 바꾸세요.

services:
  pgrelay_in:
    image: alpine/socat
    container_name: pgrelay_in
    network_mode: "service:shyni"
    command: "TCP-LISTEN:15432,fork,reuseaddr TCP:127.0.0.1:5432"
    restart: unless-stopped
    depends_on:
      shyni:
        condition: service_healthy

  pgrelay_out:
    image: alpine/socat
    container_name: pgrelay_out
    command: "TCP-LISTEN:15432,fork,reuseaddr TCP:shyni:15432"
    restart: unless-stopped
    networks:
      - default
      - app_backend

networks:
  app_backend:
    external: true
    name: backend

· default는 shyni 컴포즈의 기본 네트워크입니다. pgrelay_out은 이 네트워크로 shyni 쪽에 닿습니다.
· 아래 networks: 부분은 pgrelay_out을 플러그인 쪽 네트워크에도 붙이기 위한 것입니다. app_backend는 이 컴포즈 안에서만 쓰는 별칭이고, 실제로 가리키는 것은 external: true와 name: backend입니다. 여기서 backend는 이 플러그인이 실행되는 컨테이너(ff)가 붙어 있는 Docker 네트워크의 실제 이름입니다. 본인 환경에서 그 이름이 다르면 실제 이름으로 바꿔야 합니다.
· 네트워크 이름은 docker network ls로 목록을 보거나, docker inspect <ff 컨테이너 이름>의 Networks 항목에서 확인할 수 있습니다.
· 이렇게 두 네트워크에 함께 붙은 pgrelay_out 덕분에, 플러그인은 자기 네트워크에서 pgrelay_out:15432로 접속해 shyni의 PostgreSQL까지 닿을 수 있습니다.
· pgrelay_out의 전달 대상 shyni:15432는 shyni 서비스 이름 기준입니다.
· pgrelay_in은 shyni 컨테이너와 네트워크를 공유하므로, shyni를 재생성하면 중계도 함께 재생성해야 다시 붙습니다. 같은 컴포즈에 두고 함께 재배포하는 것을 권장합니다.
· depends_on의 service_healthy 조건은 shyni의 healthcheck가 통과한 뒤에 pgrelay_in이 붙게 합니다. 이게 없으면 재부팅 때 shyni보다 먼저 뜨려다 실패해 중계가 내려간 채로 남을 수 있습니다. shyni 서비스에 healthcheck가 없는 구성이라면 이 조건은 빼고 쓰세요.
2. 컴포즈를 재배포해 shyni와 중계가 함께 올라오게 합니다.
3. Relay 설정에 아래처럼 입력하고 연결 테스트를 누릅니다. 

중계 주소: pgrelay_out
포트: 15432
DB 이름: shyni
계정: shyni_ro
비밀번호: 공통 준비에서 만든 값

4. 성공 메시지가 나오면 그때부터 데이터베이스 정보를 활용합니다.

직접 설치(native)한 경우

PostgreSQL이 호스트에서 직접 돌고, 이 플러그인이 도는 쪽도 같은 호스트에 있으면 중계가 필요 없습니다.
1. Relay 설정에 주소 127.0.0.1, 포트 5432, DB 이름 shyni, 계정 shyni_ro를 넣고 연결 테스트를 합니다.
2. 실패하면 PostgreSQL 설정을 확인하세요.
· pg_hba.conf에 다음 줄이 있어야 합니다. 없으면 추가하고 PostgreSQL을 다시 불러오세요(서비스 재시작 또는 reload).
host  shyni  shyni_ro  127.0.0.1/32  scram-sha-256
· postgresql.conf의 listen_addresses가 접속을 허용하는지도 확인하세요.
3. 플러그인이 다른 기기나 컨테이너에서 돌고 있으면, 그 대역을 pg_hba.conf에 허용하고 listen_addresses를 열거나, Docker 절의 중계와 같은 방식으로 호스트에서 socat을 직접 실행해도 됩니다.
socat TCP-LISTEN:15432,fork,reuseaddr TCP:127.0.0.1:5432

문제 해결

· 연결 테스트가 시간 초과로 실패: 중계 컨테이너가 떠 있는지(docker ps), 네트워크 연결이 맞는지 확인하세요.
· 비밀번호 인증 실패: 공통 준비의 SQL을 다시 실행해 비밀번호를 재설정하고, Relay 설정 값과 같은지 확인하세요.
· 설정을 바꿨는데 활용이 안 됨: 접속 정보가 하나라도 바뀌면 활용이 자동으로 해제됩니다. 연결 테스트를 다시 눌러 주세요.
