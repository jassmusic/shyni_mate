휴지통 스캔 매뉴얼

작업 관리 작업 결과 설정 작업이 겹치면 기다립니다 주기적 스캔과는 따로 돕니다 지금 실행은 기다리지 않습니다 휴지통 비우기, 어떻게 처리되나 단계별 동작 상세 카드에 붙는 라벨 취소 화면 갱신

작업 관리

라이브러리와 동작을 골라 cron으로 등록해 두면, 정해진 시각에 하나씩 순차로 실행합니다. 동작은 새로고침·스캔·비우기와 그 조합 중에서 고를 수 있고, 비우기가 포함된 동작은 앞 단계가 끝난 것을 확인한 뒤 마지막에 휴지통을 비웁니다. 실행 전에 휴지통 항목을 먼저 확인해, 항목이 없으면 건너뛰고 항목이 있을 때만 그 항목의 폴더를 대상으로 새로고침·스캔을 수행합니다. 새로 없어진 파일을 찾는 전체 스캔은 주기적 스캔이 담당합니다.

작업 결과

휴지통 스캔의 실행 결과를 봅니다. 행을 누르면 단계별 소요와 집계, 비운 개수, 대상 파일, 복원된 파일, 비운 파일을 볼 수 있습니다. 대시보드에서 누른 휴지통 비우기도 여기에 '대시보드 (수동)' 작업으로 남습니다.

설정

휴지통 스캔의 VFS 새로고침 제한 시간, 작업 대기 시간, 진행 중 표시 정리 시간과 실행 이력 보관 기간을 정합니다.

VFS 새로고침 제한 시간은 폴더 새로고침이 끝나기를 기다리는 시간입니다. 기본값은 360분(6시간)이고, 이 시간을 넘겨도 새로고침이 끝나지 않으면 그 폴더는 실패로 끝나고 스캔·비우기에서 빠집니다. 새로고침 자체는 rclone 쪽에서 계속 돌 수 있습니다.

진행 중 표시 정리 시간은 진행 중 표시가 이 시간 이상 그대로면 정리하는 시간입니다. 기본값은 30분입니다. 실행 이력 보관 기간은 작업 결과 이력을 얼마나 오래 두는지 정합니다. 기본값은 30일이고, 기간이 지난 이력은 자동으로 삭제됩니다.

알려진 제한: FF가 재시작되면 실행 중이던 휴지통 스캔은 복구되지 않습니다. 주기적 스캔과 달리 다시 시작해야 합니다.

작업이 겹치면 기다립니다

휴지통 스캔은 아래 두 가지 제한 안에서 함께 돌 수 있습니다. 정해진 시각에 자리가 없으면 실패하지 않고, 자리가 날 때까지 기다렸다가 이어서 실행합니다. 기다리는 동안 작업 관리·작업 결과 목록에 '대기중' 카드가 나오고, 작업 결과에는 '대기 중' 행이 생겨 앞선 작업 이름과 기다린 시간이 표시됩니다. 같은 작업이 이미 돌거나 기다리고 있으면 중복으로 실행하지 않습니다. 작업 대기 시간은 설정에서 정합니다. 기본값은 360분(6시간)이고, 0으로 두면 기다리지 않고 바로 실패로 끝납니다.

시작할 때는 두 가지 제한을 순서대로 봅니다. 먼저 같은 모듈 안에서 같은 라이브러리가 이미 작업 중이면 동작 종류와 무관하게 시작하지 않습니다(규칙 1). 다음으로 스캔이 들어간 동작은 다른 라이브러리 스캔이 상한까지 돌고 있어도 시작하지 않습니다(규칙 2). 상한은 스캔 설정의 '라이브러리 동시 스캔 수'(기본 2)입니다. 규칙 1이 규칙 2보다 먼저 적용됩니다.

주기적 스캔과는 따로 돕니다

휴지통 스캔과 주기적 스캔은 줄이 따로입니다. 휴지통 스캔이 도는 중에도 주기적 스캔은 기다리지 않고 바로 시작하고, 반대도 마찬가지입니다. 다만 스캔이 들어간 동작은 같은 라이브러리를 두 작업이 동시에 건드리지 않습니다. 대시보드 스캔이나 주기적 스캔이 같은 라이브러리에서 돌고 있으면 스캔이 들어간 동작(스캔·새로고침 후 스캔·새로고침 후 스캔 후 비우기)에서 건너뛰고 다음 라이브러리로 넘어갑니다. 스캔 목록의 폴더 단위 스캔은 이 건너뜀에 세지 않습니다. 새로고침만·비우기만 하는 동작은 스캔과 충돌하지 않아 건너뛰지 않고 바로 실행합니다.

지금 실행은 기다리지 않습니다

'지금 실행'은 수동 실행이라 기다림 없이 바로 시작하거나 바로 거절됩니다. 같은 라이브러리가 이미 작업 중이면 동작 종류와 무관하게 거절되고, 스캔이 들어간 동작은 다른 라이브러리 스캔이 설정한 개수까지 돌고 있어도 거절됩니다. 대기 줄에 들어가지 않습니다. 돌고 있는 작업 행의 버튼은 [취소]로 바뀌어 있으니, 멈추려면 취소를 눌러 주세요.

휴지통 비우기, 어떻게 처리되나

파일이 디스크에서 사라지면 스캔이 그 파일을 '못 찾음'으로 표시하고, 못 찾은 시각을 기록합니다. 비우기를 실행하면 못 찾음 항목이 '휴지통'으로 바뀌고, 휴지통으로 바뀐 항목 중 못 찾은 지 보관 기간이 지난 것만 라이브러리에서 지워집니다. 보관 기간이 안 지난 항목은 휴지통에 남습니다.

비우기 한 번에 일어나는 일

  1. 못 찾음 → 휴지통으로 바꾸기 — 비우기를 실행하면 그 라이브러리의 못 찾음 항목이 전부 휴지통으로 바뀝니다. 이때 못 찾은 시각은 처음 기록된 그대로 유지됩니다. 바뀌는 시각으로 새로 세지 않습니다.
  2. 보관 기간이 지난 항목 지우기 — 휴지통 항목 중 못 찾은 지 보관 기간(기본 7일)이 지난 것만 라이브러리에서 지워집니다. 보관 기간은 못 찾은 시각부터 셉니다. 그래서 7일이 지난 못 찾음 항목은 휴지통으로 바뀌자마자 같은 비우기에서 바로 지워집니다. 7일이 안 지난 항목은 휴지통에 남습니다.
  3. 빈 정보 정리 — 파일이 하나도 안 남은 작품 정보가 있으면 함께 정리합니다.

못 찾음에서 휴지통으로 바뀌는 것은 비우기를 실행할 때만 일어납니다. 스캔만으로는 바뀌지 않으니, 비우기를 안 하면 못 찾음 항목은 못 찾음 상태로 계속 남습니다.

비우기는 라이브러리 전체 단위로 동작합니다. 개별 항목만 골라 비우는 기능은 shyni API에서 제공하지 않습니다.

비운 파일과 남은 파일

작업 결과 상세에서는 실제로 비운 파일과 보관 기간이 남아 남은 파일을 따로 보여 줍니다.

  • 비운 파일: 비우기 전에는 있었는데 비운 뒤에 없어진 파일입니다. 실제로 라이브러리에서 지워진 파일입니다.
  • 보관 기간이 남아 남은 파일: 비운 뒤에도 휴지통에 남아 있는 파일입니다. 못 찾은 지 보관 기간(기본 7일)이 아직 안 지나서 지워지지 않았습니다. 파일마다 못 찾은 지 며칠이 지났는지 경과일이 표시됩니다.

비운 개수가 0개인데 대상 파일이 목록에 나오는 경우가 있습니다. 비우기를 실행했지만 보관 기간이 지난 파일이 없어서 실제로 지워진 파일이 없는 경우입니다. 이런 파일들은 '보관 기간이 남아 남은 파일'에서 확인할 수 있습니다.

단계별 동작 상세

휴지통 스캔은 아래 순서대로 진행됩니다. 동작에 따라 일부 단계만 실행합니다.

  • 새로고침만: 1~2단계를 실행합니다.
  • 스캔만: 1단계와 3단계를 실행합니다. 새로고침 없이 목록 확인 후 바로 스캔합니다.
  • 비우기만: 4단계만 실행합니다. 목록 확인 없이 바로 비웁니다.
  • 새로고침 후 스캔: 1~3단계를 실행합니다.
  • 새로고침 후 스캔 후 비우기: 1~4단계를 전부 실행합니다.

1단계. 목록 확인

실행 전에 휴지통 항목을 먼저 확인합니다. 항목이 없으면 작업을 건너뜁니다. 목록을 읽지 못하면 새로고침·스캔이 들어간 동작은 실행하지 않고, 비우기만 하는 동작은 목록 없이도 실행합니다.

2단계. 새로고침

휴지통 항목이 있는 폴더마다 디렉터리 정보를 새로 읽습니다. 폴더별로 성공·실패가 나뉩니다. 일부 폴더가 실패해도 나머지 폴더는 계속 새로고침하고, 전부 실패하면 작업이 실패로 끝납니다. 결과 화면의 대상 파일 목록에서 폴더마다 새로고침 성공(OK)·실패(NG)를 볼 수 있습니다.

3단계. 스캔

새로고침이 된 폴더만 스캔해, 돌아온 파일이 있는지 확인합니다. 돌아온 파일은 휴지통에서 빠지고(복원), 여전히 없는 파일만 남습니다. 새로고침에 실패한 폴더는 스캔하지 않습니다. 스캔 결과도 폴더별로 표시됩니다.

4단계. 비우기

마지막에 휴지통을 비웁니다. 새로고침이나 스캔에서 실패한 폴더가 있으면 비우기를 하지 않습니다. 확인이 안 된 항목을 지우면 안 되기 때문입니다. 비우기 자체의 처리는 '휴지통 비우기, 어떻게 처리되나' 절을 봐 주세요.

카드에 붙는 라벨

휴지통 조회 화면의 카드에는 두 종류의 라벨이 붙습니다. 삭제 사유 라벨은 파일이 휴지통에 들어간 이유를, 상태 라벨은 지금 어떤 단계에 있는지를 보여 줍니다.

삭제 사유 라벨

카드의 설명 줄에 붙는 붉은 라벨입니다. 사유는 네 가지입니다.

  • scan_missing — 스캔하면서 디스크에서 파일을 못 찾았습니다. 가장 흔한 경우입니다.
  • manual — shyni에서 직접 삭제했습니다.
  • library_folder_removed — 라이브러리 폴더를 제거했습니다.
  • reclassified_local_extra — 로컬 부가 콘텐츠로 다시 분류됐습니다.

상태 라벨

카드 오른쪽 위에 붙는 라벨입니다. 상태는 두 가지입니다.

  • missing — 스캔이 못 찾은 상태입니다. 아직 비우기를 실행하지 않았습니다.
  • trashed — 비우기를 실행해서 휴지통으로 넘어간 상태입니다. 보관 기간이 지나면 다음 비우기에서 지워집니다.

사유와 상태는 다른 것입니다. 예를 들어 scan_missing인 파일도 비우기를 실행하기 전에는 missing, 실행한 뒤에는 trashed가 됩니다. 상태가 바뀌는 과정은 '휴지통 비우기, 어떻게 처리되나' 절을 봐 주세요.

취소

돌고 있는 작업은 작업 관리·작업 결과 화면의 [취소] 버튼으로 멈출 수 있습니다. 버튼을 누르면 확인 창이 나오고, 확인하면 취소가 진행됩니다.

  • 대기 중인 작업은 대기 줄에서 빠집니다.
  • VFS 새로고침 단계에서는 새로고침이 끝나기를 기다리는 것을 멈추고, rclone에 새로고침 중단도 요청합니다. 다만 rclone이 바로 멈추지 않을 수 있어, 새로고침 자체는 백그라운드에서 끝까지 돌 수 있습니다.
  • 스캔 단계에서는 shyni에 스캔 취소를 요청합니다. shyni에서 실행 중인 스캔은 취소 요청이 닿지 않아 계속될 수 있으니, 멈췄는지 확인하고 싶으면 shyni 웹에서 직접 확인해 주세요.
  • 비우기 중에는 취소할 수 없습니다.

취소는 지금 실행 중인 단위 하나만 멈춥니다. 대기 중인 다른 단위는 건드리지 않습니다.

화면 갱신

작업 관리·작업 결과 화면

  • 진행 중 카드는 15초마다 자동으로 갱신됩니다. 단계·진행률·경과 시간이 바뀝니다.
  • '지금 실행'을 누른 뒤에는 3초 간격으로 빠르게 갱신합니다 (90초 동안, 실제 카드가 뜨면 그 전에 끝납니다).
  • 작업 정의(이름·실행 주기·대상 라이브러리)는 자동으로 바뀌지 않습니다. 다른 화면에서 바꾼 내용은 페이지를 다시 불러와야 보입니다.
  • 작업 결과의 이력 목록은 자동으로 바뀌지 않습니다. 작업이 끝나도 목록에 반영되지 않으니, 새로고침 버튼을 눌러 주세요. 주기적 스캔 결과 화면과는 다른 점입니다.

휴지통 조회 화면

  • 조회 중일 때만 진행률이 갱신됩니다 (0.7초마다). 조회가 끝나면 목록과 개수가 한 번에 바뀝니다.
  • 전체 현황 개수는 자동으로 바뀌지 않습니다. 페이지를 다시 열거나 조회를 실행해야 최신 개수가 보입니다.
  • 목록은 기본적으로 저장해 둔 결과를 보여 줍니다. 최신 상태로 다시 계산하려면 '최신으로 조회'를 눌러 주세요. 화면에 "캐시 데이터 기준 (N분 전)"처럼 기준 시각이 표시됩니다.
  • 휴지통 개수 캐시는 기본 12시간마다 갱신됩니다. 주기는 휴지통 페이지 우측 상단에서 바꿀 수 있습니다.

메이트가 shyni·rclone과 주고받는 주기

  • VFS 새로고침 확인은 10초마다 rclone에 물어봅니다.
  • 스캔 완료 확인은 20초마다 shyni에 물어봅니다.
  • 대기 확인은 10초마다 합니다.
  • 스캔 진행률은 60초마다 기록합니다. 그래서 브라우저가 15초마다 물어도, 진행률 숫자 자체는 최대 60초마다만 바뀝니다.
